> 事实基线:**2026-09**。本领域迭代极快,涉及价格、模型版本、产品功能的数字请在引用前复核官方页面;每章开头标注该章"案例基线"。

## 一、题库设计体系

### 1. 题型分类(7 种)

| 题型 | 缩写 | 考什么 | 答题形态 |
| --- | --- | --- | --- |
| 八股题 | 【八股】 | 有稳定技术答案的机制类知识(原理、机制、判定) | 完整结构化参考答案(见下) |
| 原理深挖 | 【原理】 | 机制背后的 why、量化 trade-off | 完整结构化参考答案 |
| 品味题 | 【品味】 | 判断力、审美、取舍(无标准答案) | 2–3 个方向+适用条件+判据 |
| 开放题 | 【开放】 | 系统性思考、前瞻判断、**偏好与品味的追问**(你喜欢用什么、为什么、别的差在哪) | 讨论框架+"好答案长什么样" |
| 工程实战 | 【实战】 | 真实工程问题的解决方案设计 | 参考框架+关键决策点 |
| 场景排错 | 【排错】 | 给定故障现象,定位根因 | 排查链路与判据 |
| 场景设计(新) | 【场景】 | 在给定业务场景下做技术设计(无标准答案,言之有理即可) | 参考思路+判据 |

**题型占比(2026-09 版)**:八股 70(20.1%)/ 原理 78(22.4%)/ 品味 54(15.5%)/ 开放 54(15.5%)/ 实战 38(10.9%)/ 排错 37(10.6%)/ 场景设计 10 + 快问 7(合计 4.9%)。
无标准答案类(品味+开放+场景设计)合计约 **33%**,与八股/原理/实战形成四足鼎立——这是本次修订刻意做的倾斜:产品与生态类知识不再出"它是什么"的记忆题,一律转成"你在场景下怎么设计/怎么判断";每章末尾的"开放加餐"专收偏好型与追新型追问(主力工具/模型选择与相对优势/信息习惯/新模型发布后的动作链/开源 harness 部署试用/付费方式),用"具体、有比较、有理由、动过手"探真实使用深度、知识面与品味。

### 2. 答案结构(八股/原理题的标准格式)

每道题的参考答案按真实候选人视角组织,**加粗句连读就是可背的骨架**,正文帮你理解,细节分层存放:

- **人话版**:面试时口头能直接说出来的版本(允许口语,"我一般这么干…")
- **主线(照这条线讲)**:3–5 步,每步以一句加粗的"论点"开头(先背这句),后面 1–3 句解释机制或给例子——解决"不知道该看哪点"的问题:背骨架、懂解释、按编号顺序讲
- **补充弹药(追问再掏)**:数字、案例细节、边缘情况——初答不塞,被追问再拿出手
- **及格线 / 加分 / 红旗**:答到什么程度算及格(L2)、什么是 L3+ 加分、常见错误回答长什么样

品味/开放/场景题同样口语化:给 2–3 个合理方向、各自的适用条件和判据,不给"标准答案"。**项目类问题(ch13)一律用演进叙事作答**:遇到的问题 → 最初的方案 → 测试中发现为什么不合适(具体症状)→ 换成的方案 → 优势 → 成效——"从问题推方案",讲踩坑与修复,不讲完美设计说明书。

### 3. 难度分级(保留)

| 级别 | 定位 | 对应候选人 |
| --- | --- | --- |
| L1 | 初级:知道概念、用过工具 | 校招、实习生、刚迁移到 AI 工作流的工程师 |
| L2 | 中级:理解机制、能落地配置 | 1–3 年经验、日常重度使用 coding agent |
| L3 | 高级:懂原理、能设计系统、有量化意识 | 平台/infra 工程师、tech lead |
| L4 | 专家:能权衡架构、有失败经验、能治理 | 资深架构师、agent 平台负责人 |
| L5 | 前沿:研究级判断、能与最新论文/实践对话 | 研究员、前沿探索者 |

### 4. 面试官视角(保留,每题标注)

| 视角 | 标签 | 典型出题关注 |
| --- | --- | --- |
| 一线重度用户 | 【用户】 | 实操习惯、效率、翻车经验、工具选择 |
| Agent 平台工程师 | 【平台】 | loop 实现、上下文管理、成本、可观测性 |
| 模型/算法研究员 | 【模型】 | 训练范式、推理机制、评测方法学 |
| 架构师/技术负责人 | 【架构】 | 系统分层、边界设计、长期演进、组织落地 |
| 安全工程师 | 【安全】 | 攻击面、沙箱、权限、供应链、审计 |
| 产品/工程管理 | 【管理】 | 生态位判断、商业模式、组织效能度量 |

## 四、出题原则(v2 修订确立)

1. **只考机制,不考新闻。** 八股/原理题只保留有稳定技术答案的机制类问题(prompt caching 前缀匹配、compaction 保留策略、沙箱隔离层次……);产品发布时间线、榜单百分比、市场份额、收购案细节一律不出记忆题——这类知识只做背景板,考察转成场景题("这种评测任务怎么构造、判定怎么设计")。每题自检两问:三年后还有效吗?考的是懂技术还是记新闻?
2. **答案像真人说话。** 每道题从"书面满分答案"改写为真实候选人视角:人话版+展开+及格线/加分/红旗。正常人面试能说出口,读者能顺着逻辑理解着背。
3. **知识点自包含。** 题干和答案不依赖任何外部材料;术语用行业通用词(context engineering、compaction、KV cache、subagent、worktree、RLVR…),不造新词。
4. **数字带语境,案例带日期。** 数字尽量给来源与"截至"时间;品味/生态/开放题的案例优先取最近 1–3 个月的真实动态,每章标注案例基线;机制类知识不强行挂时间。
5. **反面观点也入题。** 多 agent 单线程派 vs 团队派、"RAG 已死"之争、自动审批该不该默认开——好的候选人应该能站在正反两面论证。

## 五、v2 修订说明(2026-08)

本次为全库重写级修订,两轮完成:

- **第一轮**:答案改版为候选人视角结构;删除全部记忆型 trivia 题(基准百分比、产品时间线、市场数据类)与全部对原参考书的引用;新增三个知识板块——agentic RAG(ch02)、coding agent 检索现实(ch03)、DeepSeek 模型×Harness 协同(ch09);新增【场景设计】题型并大幅提高无标准答案类占比;全库案例基线更新至 2026-06~08 并逐章标注。
- **第二轮(答案结构升级)**:针对"展开不够、不知道该看哪点"的问题,答案结构从"人话版+展开"升级为"**人话版 → 主线(照这条线讲,每步一句加粗论点)→ 补充弹药(追问再掏)**"——加粗句连读即背诵骨架,按编号即讲述顺序,细节与主论分层;全库 12 章统一重写。
- **新增 lorelum 工程实践题 14 道**:取材自 lorelum-packs 的 agentic-coding 实践集,分布为 ch06 会话接力三条纪律(+3)、ch07 测试与证据纪律(+6)、ch10 需求与范围纪律(+5)——覆盖目标定义反模式、来源权威分级、范围三档处置、风险配比投入、证据四元组、减法式 review 等一线纪律。
- **新增"开放加餐:偏好与品味追问"16 道(每章末节)**:主力工具与模型选择及相对优势、记忆文件个人风格、压缩触发习惯、MCP 面板取舍、权限底线、验收动作、付费方式、"只能留一个工具"的极端取舍、"最近三个月最被低估/高估"——这类题专探知识面与品味:答案要"具体、有比较、有理由",背不出、装不像。
- **新增"开放加餐二:追新与动手验证"8 道(ch01/ch09/ch11/ch12)**:信息源分层与过滤习惯、新模型发布后的动作链(看脚注→第三方复测→自己试→形成"在我任务上"的判断)、开源 harness(DeepSeek Harness)的部署试用与对比结论、值不值得换的判断框架、最近真正上手试过的发布、尝鲜筛选漏斗、团队追新的准入治理、"讲一个你最近自己折腾的东西"——探的是信息素养、时间预算意识和一手经验的密度。
- **新增 ch13 项目深挖专章(18 题,以开源项目 QuantAgent 为材料)**:把"候选人带着项目来面试"的深挖过程做成题——项目叙事(30 秒/3 分钟讲法、最难决策、"和直接问 ChatGPT 的区别")、事件驱动骨架(三入口+事件总线/去重幂等/回放设计/migrate 显式化)、agent 设计含金量(MainAgent 不做清单、submit_action_plan 唯一行动入口与执行权移交系统、run 绑定上下文工具、SubAgent 显式纪律、Policy Gate 审批与时效性规则、审计不存完整 CoT 的取舍)、两道链路排错和规模化压力测试;答案按演进叙事组织,题目自包含,也可当作任何 agent 项目面试的准备模板。
